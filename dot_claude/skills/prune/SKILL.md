description: Find and remove waste from a codebase — dead code, unreferenced files and exports, unused dependencies, duplicated logic, one-implementation abstractions, unreachable defensive branches, obsolete compat shims and always-on flags, commented-out code, stale comments, dead CI jobs and config. Works on a whole codebase (swept area by area) or on a diff (waste the change introduced, and existing code the change made obsolete). # prune — コードベースから無駄を消す

候補出し → 反証 → 適用 → 点検。**反証で「反証できなかった」と判定されたものだけを消す**。

| やりたいこと | 使うもの |
| --- | --- |
| 要らないものを消す | この skill |
| 残すコードを整理する (再利用、単純化、抽象度の調整) | `simplify` |
| バグを探す | `/code-review` |

## 登場人物

| 呼び方 | 誰か |
| --- | --- |
| **実行者** | この手順を回すあなた。範囲を決め、採否を決め、実際に消し、検証する |
| **探索エージェント** | 雛形 01 / 05 を渡された `codex exec`。候補を出す |
| **反証エージェント** | 雛形 02 を渡された `codex exec`。候補を覆そうとする |
| **点検エージェント** | 雛形 04 を渡された `codex exec`。削除後の差分を読む |
| **依頼者** | 掃除を頼んだ人 |

## 適用条件

次を満たさないなら、満たしてから始める。

- **作業ツリーが clean で、作業ブランチにいる**。prune 以外の差分は先に退避する
- **開始前に、対象のビルドとテストを実行して成功を記録できる**
- **対象範囲の外部境界を特定できる**。公開 API、他リポジトリからの利用、動的登録を
  特定できない領域は、対象から外す

**削除の影響を検知できる検証がない範囲は消さない**。何が要るかは対象で違う。

| 消すもの | 何で検知するか |
| --- | --- |
| 実行時のコード | その挙動を通るテスト |
| 設定・依存・CI・ビルド定義 | ビルドと、設定を読み込む側が通ること |
| コメント・ドキュメント | テストでは検知できない。反証で「実装と食い違っている」か「参照が無い」かのどちらかを確かめるまでが検証にあたる。リンク検査や文書ビルドがあるなら通す |

用意できないなら、先に用意するか対象から外す。
「読めない」「意図が分からない」は削除の理由にならない。

**配布物、公開 API、DB スキーマ、本番の運用設定に触れる削除はこの skill の範囲外**。
候補として報告し、判断は依頼者に上げる。聞ける相手がいないなら消さず、
手順 5 の「対象外にしたもの」に回す。

## 候補の 2 種類

| 種類 | 観点 | 反証で問うこと |
| --- | --- | --- |
| **消す** | A 未参照 / F のうち依存と CI ジョブ | **使われている証拠はあるか**。1 つでもあれば消さない |
| **消す (利用の有無で決まらない)** | B 到達不能 / E 役目を終えた / F のうち設定と生成物 | **役目がまだあるか**。到達する経路、実装と一致するコメント、入る経路が残っている分岐、消すと最終値が変わる設定 |
| **寄せる** | C 重複 / D 過剰な間接化 | 両方とも使われている。問うのは**一方に統合すると壊れるか** |

候補ごとの具体的な問いは 02 の雛形にある。実行者はこの区別だけ覚えておけばよい。

| # | 観点 | 何を探すか |
| --- | --- | --- |
| A | 未参照 | どこからも呼ばれない関数・型・定数・ファイル・アセット、使われない export、**使われない引数・設定項目・拡張点** |
| B | 到達不能 | 条件が常に偽の分岐、return 後のコード、起こりえない例外処理 |
| C | 重複 | 同じ処理が 2 箇所以上。コピペされた分岐、同じ定数の再定義 |
| D | 過剰な間接化 | 実装が 1 つしかない抽象、素通しのラッパ |
| E | 役目を終えたもの | 互換シム、常に有効なフラグ、移行用コード、コメントアウト、実態と違うコメント、廃止された機能のテスト・フィクスチャ・ドキュメント |
| F | 依存とビルド | 使われていない依存、実行されない CI ジョブ、重複した設定、リポジトリに置かれた生成物 |

E と F の一部は、利用の有無では決まらない。実態と違うコメントは現に読まれていても消せるし、
常に有効なフラグは呼ばれていても役目を終えている。反証で問うことが変わるので、
02 の雛形は候補ごとに問いを選ぶようになっている。生成物だけは、反証を通っても
消す判断を依頼者に上げる。

## モード

| モード | 対象 | 使う雛形 |
| --- | --- | --- |
| **diff** | 変更差分。差分が持ち込んだ無駄と、**差分によって不要になった既存コード** | 05 を 1 回 |
| **sweep** | 既存コードベース。ディレクトリかレイヤで割り、1 回 1 領域 | 01 を観点ごとに並列 |

sweep で最初に手を付けるのは、**外部公開されず、動的登録されず、呼び出し元が同じ領域内に
閉じているところ**。

## 前提

断片ごとにシェルが変わる環境 (Claude Code の Bash など) では、**変数は次の断片に引き継がれない**。
以下 3 行を**各断片の先頭で書き直す**。`$W` が空のまま `rm -f "$W"/01-*.report` を実行すると
ルート直下を対象にしてしまう。

```sh
W="<一時作業領域>/prune"                   # 対象リポジトリの外に置く
S="$HOME/.claude/skills/prune/prompts"     # この skill の置き場所
T="<対象リポジトリ>"
```

最初に 1 回だけ:

```sh
command -v codex >/dev/null || { echo "codex CLI が要る"; exit 1; }
mkdir -p "$W"
test -z "$(ls -A "$W")" || { echo "$W に前回の残りがある。別の名前にする"; exit 1; }
```

`${PIPESTATUS[0]}` は bash に依存するが、同じ断片の中で取るので、断片を bash で実行すれば足りる。

雛形の番号はファイルの識別子で、手順番号ではない (05 は diff モードの候補出しに使う。
03 は無い。手順 3 の適用は実行者がやる)。

プロンプト内のパスは絶対パス。変数は引用する。探索・反証・点検は `-C "$W"` と
`--sandbox read-only` で起動する。プロンプトの禁止文ではなく、この指定で書き込みを縛る。

## 手順

### 0. 範囲と基準点を決める (実行者)

決めるのは、モード、対象パス、走らせる観点、ビルドとテストのコマンド、外部境界、
そして diff モードなら比較基準 (PR なら取り込み先ブランチ、単独コミットならその親。
判断がつかないなら依頼者に聞く。聞けないなら sweep にする)。

```sh
cd "$T"
test -z "$(git status --porcelain)" || { echo "clean にしてから"; exit 1; }
git symbolic-ref -q HEAD >/dev/null || { echo "detached HEAD。作業ブランチを作る"; exit 1; }
git rev-parse HEAD > "$W/START" || exit 1
<ビルドとテストのコマンド> 2>&1 | tee "$W/baseline.log"; rc="${PIPESTATUS[0]}"
echo "exit=$rc" >> "$W/baseline.log"
test "$rc" = 0 || { echo "baseline が失敗している。prune を始める前に直す"; exit 1; }
```

終了コードは `$?` ではなく `${PIPESTATUS[0]}` で拾う。`$?` は `tee` の結果を拾うことがある。
`baseline.log` からは、終了コードのほかに**後で比較する指標**も拾えるようにしておく。
テストの件数や警告数の取り方はプロジェクトごとに違うので、ここで決めて記録する。

diff モードなら差分も作る。

```sh
base="$(git merge-base <比較基準> HEAD)" || { echo "比較基準が解決できない"; exit 1; }
git diff "$base"..HEAD > "$W/target.diff" || exit 1
test -s "$W/target.diff" || { echo "差分が空。比較基準を見直す"; exit 1; }
```

### 1. 候補出し

雛形をコピーして `{{...}}` を埋める。**未置換が残っていたら進まない**。

sweep モード:

```sh
KINDS="A B C D E F"   # 既定は全観点。外すなら手順 0 で決め、外した理由を報告に書く
for K in $KINDS; do sed "s/{{観点}}/$K/g" "$S/01-find.md" > "$W/01-$K.md" || exit 1; done
# → 各ファイルの残りの {{...}} を埋める
for K in $KINDS; do
  test -s "$W/01-$K.md" || { echo "01-$K.md がない"; exit 1; }
  grep -q "{{" "$W/01-$K.md" && { echo "01-$K.md に未置換あり"; exit 1; }
done
rm -f "$W"/01-*.report          # 前回の残りを今回の成功と誤認しないため
pids=""
for K in $KINDS; do
  codex exec -C "$W" --sandbox read-only --skip-git-repo-check \
    -o "$W/01-$K.report" - < "$W/01-$K.md" &
  pids="$pids $!"
done
ng=0; for p in $pids; do wait "$p" || ng=1; done   # 引数なしの wait は失敗を返さない
test "$ng" = 0 || { echo "探索エージェントが失敗した"; exit 1; }
for K in $KINDS; do test -s "$W/01-$K.report" || { echo "01-$K が空"; exit 1; }; done
```

候補が無い観点でも雛形は「なし」と書かせるので、**空の report は失敗**を意味する。
埋めた本文に `{{` を含む例を書いたときは未置換の検査に引っかかる。その箇所だけ確認して進む。

diff モード:

```sh
rm -f "$W/05.md"; cp "$S/05-diff.md" "$W/05.md" || exit 1   # → 埋める ($W/target.diff を渡す)
grep -q "{{" "$W/05.md" && { echo "未置換あり"; exit 1; }
rm -f "$W/05.report"
codex exec -C "$W" --sandbox read-only --skip-git-repo-check -o "$W/05.report" - < "$W/05.md" \
  && test -s "$W/05.report" || { echo "05 が失敗、または空"; exit 1; }
```

実行者が候補を `$W/candidates.md` に統合する。重複を統合し、通し番号を振り直し、
**種類 (消す / 寄せる) と、コミット単位になる区分**を付ける。区分は sweep なら観点 A〜F、
diff なら I / II。外部境界にかかるものは候補リストから外し、
手順 5 の「対象外にしたもの」に回す。

### 2. 反証

```sh
rm -f "$W/02.md"; cp "$S/02-refute.md" "$W/02.md" || exit 1   # → 埋める ($W/candidates.md を渡す)
grep -q "{{" "$W/02.md" && { echo "未置換あり"; exit 1; }
rm -f "$W/02.report"
codex exec -C "$W" --sandbox read-only --skip-git-repo-check -o "$W/02.report" - < "$W/02.md" \
  && test -s "$W/02.report" || { echo "02 が失敗、または空"; exit 1; }
```

全候補に判定が付いているかを実行者が数えて確かめる。落ちている候補は消さない。
消せる候補が 1 件も無ければ、適用と点検を飛ばして手順 5 に進む。

| 判定 | 意味 | 扱い |
| --- | --- | --- |
| **反証された** | 上の「反証で問うこと」に対して、残す理由が見つかった | 消さない |
| **反証できなかった** | 該当する経路をすべて当たって、何も見つからなかった | **これだけ消す** |
| **判断保留** | 確かめる手段がない、確かめきれなかった | 消さない。報告に回す |

1 回に入れる候補が多いと後半が雑になる。候補 1 件ずつ十分に検証できない長さなら分割する
(経験的には 30 件あたりが目安)。

### 3. 適用 (実行者。雛形はない)

**1 区分を 1 コミットにする** (sweep なら 1 観点、diff なら I / II)。区分をまたいで混ぜない。

```sh
cd "$T"
# 「反証できなかった」と判定された候補だけを消す
<ビルドとテストのコマンド> 2>&1 | tee "$W/after-<区分>.log"; rc="${PIPESTATUS[0]}"
echo "exit=$rc" >> "$W/after-<区分>.log"
test "$rc" = 0 || { echo "失敗。stage しない。この断片を抜けたら、下の破棄手順を実行する"; exit 1; }
<手順 0 で決めた指標を baseline のログと after のログから取り出して比べるコマンド> || exit 1
# 指標も下の「破棄する条件」に当たらないことを確かめてから stage する
git add -- <触ったパス>                  # -A は使わない。ビルドの生成物まで入る
git diff --cached                        # 削除と機械的な後始末だけか、自分の目で見る
git commit -m "prune: <区分> ..." || { echo "コミットできていない"; exit 1; }
test -z "$(git status --porcelain)" || { echo "コミットに入らなかった変更が残っている"; exit 1; }
```

反証にかけるのは候補そのものだけでよい。削除に伴う機械的な後始末 —
import の整理、呼び出し元の引数削除、依存を消したときの lockfile 更新 — は反証を通さず、
同じコミットに入れる。**それ以外**、つまり名前の変更、書き直し、整形、挙動の変更は入れない。
「寄せる」候補では、一方を他方の呼び出しに置き換えて消すところまで。

次が起きたら、そのコミットを作らずに変更を破棄する。

- ビルドかテストが失敗した
- 意図して消したテスト以外に、実行されるテストが減った
- 警告が baseline より増えた

破棄するのは**その区分でまだコミットしていない変更だけ**。前の区分のコミットは残す。
tracked の変更は `git restore -- <触ったパス>`、ビルドが作った未追跡ファイルは
`git status --porcelain` で名前を確かめてから消す。**`git clean -fd` のような一括削除は使わない**
(依頼者の未追跡ファイルまで消える)。

候補が多い観点では、コミット前に候補を数件ずつ適用して都度テストすると、原因を切り分けやすい。

### 4. 点検

```sh
cd "$T"
test -z "$(git status --porcelain)" || { echo "未コミットの変更が点検差分に入らない"; exit 1; }
git diff "$(cat "$W/START")"..HEAD > "$W/pruned.diff" || exit 1
test -s "$W/pruned.diff" || { echo "削除の差分が無い"; exit 1; }
rm -f "$W/04.md"; cp "$S/04-inspect.md" "$W/04.md" || exit 1   # → 埋める
grep -q "{{" "$W/04.md" && { echo "未置換あり"; exit 1; }
rm -f "$W/04.report"
codex exec -C "$W" --sandbox read-only --skip-git-repo-check -o "$W/04.report" - < "$W/04.md" \
  && test -s "$W/04.report" || { echo "04 が失敗、または空"; exit 1; }
```

見るのは、**消しすぎ** (挙動が変わる削除)、**消し残し** (削除で孤立した関数・import・依存・
テスト・ドキュメント)、**削除以外の変更**。

危険な削除が出たら、その区分のコミットから問題の候補だけを取り除く。まだ共有していない
作業ブランチならコミットを作り直す。共有済みで履歴を書き換えられないなら `git revert` して、
残す候補を別コミットで入れ直す (この場合だけ 1 区分が 2 コミット以上になる)。
消し残しが出たら `$W/candidates.md` に追記し、番号・種類・区分を付けて手順 2 から回す。
どちらの場合も、**直したら手順 3 の検証からやり直す** (ビルドとテスト、指標の比較、
差分の作り直し、点検)。点検だけやり直して終わりにしない。**終わりの条件は、危険な削除がなく、新しい消し残しが
出ず、削除以外の変更が残っておらず、最後のテストが通り、作業ツリーが clean であること**。

### 5. 報告

- **消したもの** — 区分ごとに、何を、なぜ消せると判断したか。コミットと削除行数 (参考値)
- **消さなかったもの** — 反証された候補、判断保留の候補と、その理由
- **対象外にしたもの** — テストがない、外部境界にかかる、依頼者の判断が要る
- **検証** — 開始コミット、適用コミット、実行したコマンドと結果、baseline との差。
  やっていない検証があれば明記

## 落とし穴

- **「未参照」は言語とツールによって嘘をつく**。動的言語ほど静的解析の 0 件は当てにならない。
- **そのコードのためだけにあるテストは、生きている証拠にならない**。プロダクトコードから
  死んでいるなら、テストごと消す候補になる。
- **消した量を成果にしない**。判断保留を「たぶん大丈夫」に倒し始めたら止める。
- **生成コードの中身は直さない**。生成元を直すか、対象から外す。
  生成物をリポジトリに置いていること自体は F の候補にしてよいが、消す判断は依頼者に上げる
  (手順 5 の「対象外にしたもの」に回す)。
- **依存を消したら lockfile を更新する**。lockfile 自体は候補にしない。
- **「使っていない」と「今は通らないが仕様上必要」は違う**。エラー処理、リカバリ経路、
  異常系、rollback 用フラグ、移行のための互換分岐は、平常時に到達しないだけのことがある。
