## やり方

- **参照は自分で探す**。名前での grep だけで済ませず、その言語での呼ばれ方 (継承、インタフェース
  実装、デコレータ、エントリポイント登録、テストからの利用) を確認する
- 既に出力があるなら、未使用検出ツールの結果、コンパイラの警告、カバレッジを参考にしてよい。
  ただし**ツールの出力をそのまま候補にしない**。1 件ずつ自分で確かめる
- 「読みにくい」「設計が良くない」は今回の対象外。**要らないもの**だけを探す
- 生成されたコードとベンダリングされた依存は、**中身**を候補にしない。
  ただし観点 F では、生成物をリポジトリに置いていること自体は候補にしてよい。
  その候補には「消すかどうかは依頼者の判断が要る」と書き添えること
- lockfile の中身は候補にしない (依存を消したときの更新は、消す側の作業)

## 報告 (標準出力に日本語で)

候補ごとに、次の形式で。**多く挙げることを目的にしない。確度の高いものから順に。**

```
### 候補 <番号>
場所      : <パス>:<行>  (複数箇所なら全部)
何か      : <関数名/ファイル名/依存名など。1 行で何をするものか>
観点      : {{観点}}
根拠      : <なぜ要らないと言えるか。どう探して参照が無いと確かめたか。使ったコマンドも書く>
消し方    : <消すだけか、呼び出し元の修正も要るか。連鎖して孤立するものがあれば書く>
残す理由があるとすれば: <自分でも思いつく反論。無いなら「思いつかない」>
確度      : 高 / 中 / 低
```

最後に、次の 2 つを分けて書く:

- **確度が低い理由**: 静的に追いきれなかった箇所、この言語・フレームワークで動的参照が
  起こりうる箇所を、正直に列挙する
- **他の観点で気づいたこと**: 1 行ずつ

見つからなければ「なし」と書く。無理に候補を作らないこと。
