**この差分はすでに適用済みで、{{対象パス}} の現在の状態が削除後のコードです。** 差分だけでなく、

## 見ること

### 1. 消しすぎていないか

削除によって挙動が変わる箇所を探す。特に:

- 副作用のある行が、値を使っていないという理由で消えていないか
  (ログ、メトリクス、ロック取得、初期化、キャッシュ暖機、監査記録)
- 例外処理・リトライ・タイムアウト・境界チェックが、「到達しない」という理由で消えていないか。
  それは平常時に到達しないだけかもしれない
- 引数・設定項目・フィールドの削除が、外部から渡される値と噛み合っているか
  (API のリクエスト、設定ファイル、保存済みデータ)
- デフォルト値や初期化が消えて、暗黙のゼロ値に変わっていないか
- 消された分岐が、本当に到達不能だったか。自分で条件を追って確かめる

### 2. 消し残しがないか

削除によって新しく孤立したものを探す。削除は連鎖する。

- 消された関数だけが呼んでいた関数、その関数だけが使っていた定数・型・ファイル
- 使われなくなった import、依存、設定項目
- 消された機能のためだけにあったテスト、フィクスチャ、モック
- 消された機能を説明しているコメント、ドキュメント、README の記述
- 依存を消したのに更新されていない lockfile

### 3. 削除以外のことをしていないか

差分の中に、名前の変更、書き直し、整形、挙動の変更が混じっていないか。
混じっているなら、それがどこかを指摘する。

## 報告 (標準出力に日本語で)

```
## 危険な削除
<該当箇所 → なぜ挙動が変わるか → どう直すか (戻す / 一部だけ戻す)>

## 消し残し
<該当箇所 → なぜ孤立したと言えるか>

## 削除以外の変更
<該当箇所 → 何をしているか>
```

該当なしの節には「なし」と書く。

最後に、**この差分をこのまま取り込んでよいか**を一言で。取り込めないなら、何を直せば取り込めるか。
忖度せず、厳しく見ること。褒め言葉は不要です。
