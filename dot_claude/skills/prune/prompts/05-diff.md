## 探すもの (この 2 つを分けて報告する)

### I. この変更が持ち込んだ無駄

- 追加されたが、どこからも呼ばれていないもの
- 既にコードベースにあるものの再実装 (同じ処理、同じ定数、同じユーティリティ)
- 使われない引数・設定項目・拡張点 (使われていないので「消す」)
- 素通しのラッパ、実装が 1 つしかない抽象 (両方使われているので「寄せる」。
  呼び出し元が 1 つというだけでは候補にしない。素通しであること、または実装が
  1 つしかないことを確かめる)
- 起こりえない条件の防御、二重にかかっている検査
- 変更の作業中に残ったもの — コメントアウト、デバッグ出力、TODO、未使用の import
- 足されたが使われていない依存、動かない CI ジョブ、既存と重複する設定、
  リポジトリに追加された生成物 (生成物は「消すかどうかは依頼者の判断が要る」と書き添える)

### II. この変更によって不要になった既存コード

**こちらが本命です。** 変更は、それまで必要だったものを不要にすることがある。

- 新しい実装に置き換わったのに残っている古い実装・古い経路
- 新しい経路ができたことで、誰も通らなくなった分岐
- 移行のための互換シム、フラグ、両対応コードのうち、もう片方が消えたもの
- 置き換え前の実装だけをテストしていたテスト、フィクスチャ
- 実態と合わなくなったコメント、ドキュメント、設定のコメント
- 古い実装だけが使っていた依存、CI ジョブ、設定項目

## やり方

- 参照は自分で探す。名前での grep だけで済ませず、その言語での呼ばれ方を確認する
- 「読みにくい」「設計が良くない」は対象外。**要らないもの**だけを探す
- 差分の意図そのものへの異論は書かない (それはレビューの仕事)

## 調べる範囲

対象リポジトリの中と、上に挙げた外部境界まで。外部リポジトリ、本番環境、稼働中のデータなど、
ここから確かめられないものは「確かめられなかった」として扱い、断定しないこと。

## 報告 (標準出力に日本語で)

I と II を分け、候補ごとに:

```
### 候補 <番号> [I または II] [消す / 寄せる]
場所      : <パス>:<行>
何か      : <1 行で>
根拠      : <なぜ要らないと言えるか。どう確かめたか。使ったコマンドも書く>
消し方    : <消すだけか、呼び出し元の修正も要るか>
残す理由があるとすれば: <自分でも思いつく反論。無いなら「思いつかない」>
確度      : 高 / 中 / 低
```

種類は、使われていないので消せるなら「消す」、両方使われているが一方に統合できるなら「寄せる」。

最後に、静的に追いきれなかった箇所を列挙する。
見つからなければ「なし」。無理に候補を作らないこと。
