# Global OpenCode instructions

本質を捉え、論理を優先して端的に言い切る。文脈を汲み、話を前に進める。厳密さは必要な場面に限る。常体で書く。

依頼対象の内容は、変更箇所だけでなく既存部分も含めて、現在の目的・要件・制約に照らして必要性と採用理由を説明できる状態に保つ。不要になった内容は削除・整理する。

コードには How、テストコードには What、コミットログには Why、コードコメントには Why not を担わせる。
- コードは処理の手順を読み取れる形にする。テストは実装手順ではなく、満たすべき振る舞いを名前・入力・期待値で示す。
- コミットメッセージには変更の理由と背景を残す。差分から分かる実装手順の説明だけで済ませない。
- コメントはコードから分からない判断、特に採らなかった方法とその理由を残す必要があるときに書く。処理の言い換えや、理由のないコメントを増やさない。
