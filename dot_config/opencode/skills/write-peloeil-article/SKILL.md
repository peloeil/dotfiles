# peloeil の技術記事を書く

著者が満足した4つの公開記事を、文体と構成の判断材料にする。新規執筆や大きな構成変更では[公開記事の観察](references/style-evidence.md)を読み、小さな修正では関係する箇所を確認する。判断に迷ったらリンク先の該当節に戻る。表面の語句や章立てを模写せず、その記事が誰のどんな疑問・作業に応えるかを先に定める。

4記事は書き方の幅を示す。最新の記事や添削記録の多い記事を標準形にしない。[strlen の添削記録](references/editorial-decisions.md)は、方式の比較、性能の説明、関連例、図の編集で同種の課題があるときに参照する個別事例である。現在の依頼を優先し、過去の解決策は目的と条件が合う場合に使う。

## 着手

- 既存原稿の編集では全体を読み、題名、導入、各節、結びが担う役割を把握する。新規執筆では、想定読者の前提、読後に理解・実行できてほしいこと、記事で扱う範囲を決める。文脈から判断できることは質問せず進める。
- 現在の依頼と記事の目的を優先する。入門、実践手順、公式文書の補助、コードの仕組みの解説では、必要な説明の量も順序も違う。外部資料と一緒に読む記事を、単独で全手順を完結させる記事に変えない。
- 技術的な事実は対象のバージョンや実装を確かめる。公開記事は文体・構成の手本であり、新しい記事の技術仕様を保証する資料ではない。

## 説明を組み立てる

- 題名は想定読者に内容や読む理由が伝わるものにする。誘いや意外性を使うか、対象を端的に示すかは題材による。強い技術的主張には本文で対象・条件・根拠を示す。
- 導入で読者の知る状況や操作と記事の目的を結ぶ。前提・対象・記事が担う範囲は、読者が迷わない時点までに示す。細かな例外で導入を埋めない。
- 節の順序は、読者がそこまでに知ったことを使って次を読めるように決める。疑問を解く流れ、作業手順、並列の選択肢、全体像から詳細へ進む構成を、説明の目的に合わせる。全体像で予告し、詳細で説明し、節の終わりで到達点を確認する反復には役割がある。
- 用語や記号は、その意味が必要になる説明までに理解できるようにする。操作例・設定・コードを先に示し、直後に意味を解きほぐす順序も使える。名前の初出ごとに定義を挟む必要はない。共通の記法は先にまとめ、想定読者が知ることは省ける。同じ名前の対象が環境や段階によって変わるときは、どれを指すか明示する。
- 見出しは、その時点の読者に伝わり、直後の内容と合うものにする。記事が解き明かす操作や工夫では、目的・制約・理由をつなぐ。前提として採用する構成や個人の好みに、技術的な優位性を作り足さない。比較の詳しさも記事の約束に合わせる。方式の理解が目的なら各方式の工夫を扱い、選択肢の紹介なら選ぶための特徴を示す。
- 例、コード、コマンド、図表は、そこで説明する性質を確かめられるものを選ぶ。本文と条件・値・向きを揃え、必要な説明を近くに置く。各方式の理解を前提にする比較図は、個別の説明を終えてから整理に使う。実装を抜粋・簡略化した場合は、原典と変更した範囲、説明上の前提を示す。

説明の深さも選べるようにする。基本操作だけで先へ進めるなら、詳しい仕組みは折りたためる。別構成の手順や通しの実装にも折りたたみを使える。その経路を読む人に必要な条件と説明は揃える。対応表・選択肢・操作一覧は表や箇条書きで示し、理由のつながりは文章で追えるようにする。図は配置・依存・変化など、本文だけでは追いにくい関係に使い、形式や枚数は固定しない。

## 著者の声と根拠

- 本文は「です・ます」を基調にする。見出し・表・箇条書きは常体や体言止めでもよい。「自分／私」や熱量は原稿と題材に合わせる。呼びかけ、問いかけ、短い感想、括弧内の軽口も著者の声として生かし、技術的な説明に役立つことだけを残す条件にしない。本人から得ていない体験談や好みは作らず、過去の冗談を別の記事へ移植しない。
- 対象と動作を具体的に書く。接続語は、理由、言い換え、次の操作など、前後の関係や説明の進行に合わせて使う。短さ自体を目的にせず、必要な説明の一段階は残す。
- 確認できた挙動、資料に書かれた理由、実装からの推論、測定結果、個人の好みを区別する。断定できることは明確に書き、未確認の部分だけを限定する。重要な技術的主張は対象に対応する一次資料や実行結果に当たる。

## 推敲して渡す

指摘箇所だけを継ぎ足さず、題名と導入の約束、前提、見出し、例、結びまで通して整合させる。不要になった説明は整理し、機能している文章は一律に書き換えない。想定した読み方で、記事が担う説明を読み戻さずに追えるか、外部資料に任せた部分がわかるか、各部分を残す理由があるかを確認する。結びは要点の整理、作業の到達点、試すことへの誘いなど、本文の目的に合わせる。

成果物と、構成上の主要な判断・未確認の事実だけを簡潔に報告する。編集用のチェック項目を記事本文に載せない。
